# CAMIE 网站后台管理使用手册

> 适用对象：内容作者、内容审核人员、网站管理员  
> 适用范围：文章发布、栏目调整、静态化生成及常见问题处理

## 1. 使用前须知

后台保存的是数据库中的最新内容，网站前台展示的是已经生成好的静态页面。部分后台操作完成后，还需要执行静态化，前台页面才会更新。

请牢记：

- 普通内容编辑按后台提示操作即可。
- 已发布文章更换栏目后，必须重新“生成全站”。
- 修改栏目结构、模板、站点基础信息后，必须重新“生成全站”。
- 看到静态化任务“成功”后，还要到网站前台检查实际展示效果。

不同账号看到的菜单可能不同，以管理员分配的权限为准。

## 2. 登录与账号权限

打开管理员提供的后台地址，输入用户名、密码和验证码（如已启用），然后单击“登录”。

系统常用角色如下：

| 角色 | 主要工作 |
| --- | --- |
| 内容作者 | 新建、编辑文章，设置发布栏目，提交审核，管理本人内容 |
| 内容审核 | 在“待审核”中审核文章，填写通过或驳回意见 |
| 管理员 | 管理全部内容、栏目、模板、用户、权限和静态化任务 |

如果登录后没有相应菜单，或者操作时提示“没有授权”，请联系管理员检查账号角色和菜单权限，不要反复提交。

## 3. 文章发布标准流程

菜单位置：**内容管理 → 图文管理**。

### 3.1 新建文章

1. 进入“图文管理”。
2. 单击新增按钮，选择相应内容类型。
3. 填写标题、作者、来源、发布时间、摘要、正文、封面等内容。
4. 先保存为草稿。
5. 在文章列表中找到该文章，单击“栏目”。
6. 先在左侧选择模板，再在右侧勾选发布栏目。
7. 确认无误后保存栏目设置。
8. 单击“提交审核”。

注意：

- 新闻、视频、数据、报刊可以选择的栏目范围不同，以弹窗实际显示为准。
- 一级栏目和子栏目都可以选择。
- 一篇文章可以投放到多个栏目，也可以跨模板选择栏目。
- 审核中的文章不能修改栏目或正文；如需修改，应先撤回审核。

### 3.2 审核文章

菜单位置：**内容管理 → 待审核**。

1. 找到待审核文章并打开审核。
2. 检查标题、正文、附件、图片、来源、发布时间和发布栏目。
3. 审核通过时，可填写通过原因。
4. 审核不通过时，必须填写明确的驳回原因，方便作者修改。

所有审核节点通过后，文章变为“已发布”。系统会自动尝试生成该文章详情页及相关页面。发布完成后，建议到网站前台检查文章详情和栏目列表。

## 4. 已发布文章更换栏目

这是日常操作中最容易遗漏静态化的一项。

### 4.1 后台操作

1. 进入 **内容管理 → 图文管理**。
2. 搜索并找到需要调整的已发布文章。
3. 单击该文章右侧的“栏目”。
4. 左侧选择模板，右侧勾选新的栏目。
5. 取消不再发布的旧栏目。
6. 检查“已选栏目”列表，确认无误后保存。

栏目设置保存后，数据库中的投放关系会立即变化，但网站前台仍可能保留旧的静态页面。

### 4.2 必须执行生成全站

1. 进入 **基础配置 → 静态化管理**。
2. 确认页面顶部“静态化服务监控”显示“运行中”。
3. 在“批量操作”中单击“生成全站”。
4. 在确认提示中继续执行。
5. 等待任务状态变为“成功”，不要在任务运行时重复单击。
6. 到网站前台分别检查：
   - 文章是否已从旧栏目移除；
   - 文章是否已出现在新栏目；
   - 文章详情页是否可以正常打开；
   - 首页或其他推荐区域是否展示正确。

更换栏目需要生成全站，是因为这项操作可能同时影响旧栏目列表、新栏目列表、文章详情导航以及首页等引用位置。只生成详情页不能保证旧栏目中的文章被移除。

## 5. 哪些操作完成后要静态化

| 后台操作 | 是否需要手动静态化 | 建议操作 |
| --- | --- | --- |
| 新文章审核通过并发布 | 通常自动生成 | 到前台检查；未更新时生成全站 |
| 管理员编辑已发布文章正文 | 通常自动刷新相关页面 | 到前台检查；未更新时生成全站 |
| 已发布文章更换、增加或移除栏目 | **必须** | **生成全站** |
| 文章下线或删除 | 系统会尝试删除相关静态内容 | 到前台检查；仍有残留时生成全站 |
| 新增、修改、启用、停用或删除栏目 | **必须** | **生成全站** |
| 修改栏目名称、层级、访问路径或绑定模板 | **必须** | **生成全站** |
| 修改模板内容或模板访问路径 | **必须** | **生成全站** |
| 修改站点名称、Logo、页头、页脚等全局信息 | **必须** | **生成全站** |
| 只修改首页展示内容、首页广告或首页链接 | 需要 | 可先生成首页；不确定时生成全站 |
| 批量导入、同步或调整多篇已发布文章 | 需要 | 处理完成后统一生成全站 |
| 修改专题及其内容 | 需要 | 生成专题页；涉及全站入口时生成全站 |
| 开启或关闭首页整体变灰 | 需要 | 生成首页；需要全站一致时生成全站 |

原则：如果不确定应该生成哪一种，选择“生成全站”最稳妥。

## 6. 静态化管理按钮说明

菜单位置：**基础配置 → 静态化管理**。

| 按钮 | 作用 | 常见使用场景 |
| --- | --- | --- |
| 生成全站 | 重新生成首页、栏目页、详情页等全站内容 | 换栏目、改栏目结构、改模板、批量调整内容 |
| 生成首页 | 只刷新首页相关页面 | 修改首页展示、首页广告、首页链接、首页变灰 |
| 生成栏目页 | 批量刷新栏目列表页 | 栏目列表显示不正确，但详情页无变化 |
| 生成详情页 | 批量刷新文章详情页 | 详情模板更新或多篇详情需要重建 |
| 生成专题页 | 批量刷新专题页面 | 专题内容或专题模板变化 |

页面中的“单页操作”适合只处理某一个首页、栏目、文章详情或专题；影响范围不明确时，应使用“生成全站”。

## 7. 如何判断生成成功

静态化前后按以下顺序检查：

1. “静态化服务监控”显示“运行中”。
2. 提交任务后出现任务记录。
3. 任务状态依次经过“等待执行”或“执行中”，最终显示“成功”。
4. 查看生成文件数量和最后静态化时间是否更新。
5. 必要时打开“静态化日志”，确认没有失败记录。
6. 到网站前台检查实际页面。

仅看到“请求已提交”不代表任务已完成，应等待最终状态为“成功”。

如果浏览器仍显示旧内容，可以先强制刷新页面（Windows 通常使用 `Ctrl + F5`）；生产环境如使用了 CDN 或代理缓存，还应联系运维人员刷新缓存。

## 8. 常见问题

### 8.1 提示 `unauthorized`

含义：后台与静态化程序之间的访问令牌不一致，或后台连接到了错误的静态化服务地址。

处理方法：

1. 不要反复单击“生成全站”。
2. 记录报错时间和完整提示。
3. 联系系统管理员检查“系统设置 → 静态化设置”中的服务地址、令牌名称，以及服务器环境变量中的令牌值。

普通内容人员不要自行修改静态化地址、输出路径或令牌名称。

### 8.2 提示“静态化程序访问令牌未配置”

含义：后台指定的令牌环境变量尚未在服务器上配置。

处理方法：联系系统管理员配置对应环境变量并重启后台服务。

### 8.3 静态化服务显示“已停止”

先单击页面上的“刷新”。如果仍为“已停止”，联系运维人员启动静态化服务。服务恢复为“运行中”后再提交任务。

### 8.4 任务长时间处于执行中

1. 不要重复提交同类任务。
2. 单击“刷新任务”查看最新状态。
3. 查看“静态化日志”。
4. 如长时间无变化，记录任务时间并联系管理员。

### 8.5 显示生成成功，但前台内容没有变化

依次检查：

1. 当前访问的是不是正确的网站环境。
2. 是否执行了正确的生成类型。
3. 已发布文章换栏目后是否执行了“生成全站”。
4. 浏览器是否仍有缓存，尝试 `Ctrl + F5`。
5. 生产环境是否存在 CDN 或代理缓存。

### 8.6 文章不能修改栏目

常见原因：文章正在审核中。作者应先撤回审核，再调整栏目并重新提交；已经发布的文章由有权限的作者或管理员调整。

## 9. 日常操作检查清单

### 发布文章

- [ ] 标题、正文、来源、作者和发布时间正确
- [ ] 图片、附件和链接可以正常打开
- [ ] 发布栏目选择正确
- [ ] 已提交并完成审核
- [ ] 前台详情页和栏目列表显示正常

### 更换文章栏目

- [ ] 已选择新栏目
- [ ] 已取消旧栏目
- [ ] 已保存栏目设置
- [ ] 已执行“生成全站”
- [ ] 静态化任务最终状态为“成功”
- [ ] 已检查旧栏目、新栏目、详情页和首页

### 修改栏目或模板

- [ ] 已确认修改不会造成访问路径重复
- [ ] 已保存修改
- [ ] 已执行“生成全站”
- [ ] 已抽查首页、栏目页和文章详情页

## 10. 管理员注意事项

- “系统设置 → 静态化设置”属于运行配置，普通内容人员不应修改。
- 修改静态化服务地址、输出路径或令牌名称后，应确认后台已加载新配置，再进行生成测试。
- 静态化令牌属于敏感信息，不要写入本使用手册、截图、聊天记录或公开文档。
- 正式环境进行栏目路径、模板或全站结构调整前，建议先备份并选择访问量较低的时间操作。
- 全站生成完成后，应至少抽查首页、一级栏目、二级栏目和文章详情页。
