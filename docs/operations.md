# 运维与排障手册

## 1. 日常巡检

每个站点至少检查：

```bash
systemctl is-active portal-static-caam
curl --fail http://127.0.0.1:9142/healthz
journalctl -u portal-static-caam --since '1 hour ago' --no-pager
```

还应检查：

- 数据库连接数和查询延迟；
- 输出磁盘容量、inode 和目录权限；
- 最近任务成功率、耗时和生成文件数；
- 管理后台静态化日志中的失败和中断；
- 线上入口、关键栏目和文章 URL；
- Web 服务器/CDN 是否仍指向正确产物目录。

`/healthz` 只代表进程可响应，不代表数据库查询、模板、输出权限和完整生成一定正常。至少保留一个定期的小范围生成探针或人工抽查流程。

## 2. 日志和任务证据

排障时记录：

- 站点、driver、二进制版本/提交号；
- 配置文件路径和配置 hash，禁止记录密码或 Token；
- 后台用户、操作时间和任务 ID；
- job 的 `kind`、`status`、`progress`、`error`；
- 生成前后文件数量和目标路径；
- 后台、静态化服务和 Web 服务器对应时间段日志。

job 只保存在进程内存中，24 小时后或进程重启后不可查询。需要长期审计时以管理后台静态化日志和集中日志系统为准。

## 3. 常见故障

### 服务无法启动

检查：

1. `driver` 是否已注册；
2. Token 环境变量是否为空；
3. 端口是否被占用；
4. 配置路径、模板和源目录是否存在；
5. DSN/schema 是否冲突；
6. 数据库是否可达、账号是否有权限；
7. 适配器是否缺少标准 Operations。

### 后台显示静态化服务离线

- 在后台主机上请求静态化服务 `/healthz`，不要只在个人电脑测试。
- 检查“静态化程序访问地址”是否包含正确协议、主机和端口。
- 检查防火墙、容器网络或主机回环地址语义。
- 如果后台和静态化服务不在同一主机，`127.0.0.1` 不能跨主机使用。

### 返回 `401 unauthorized`

- 后台设置中填写的是环境变量名称，不是 Token 值。
- 后台进程和静态化进程必须都注入该名称，且值完全相同。
- 更新环境变量后重启对应进程。
- 检查反向代理是否保留 `Authorization` 请求头。

### 返回 `409` 或已有任务执行

每个站点只允许一个活动批任务。查询响应中的 `active_job`，等待结束或通过 DELETE job 取消。不要通过重启服务强制清除，除非确认任务已经无法响应；重启会丢失内存任务记录。

### 任务变为 `interrupted`

- `error` 包含 canceled：用户或调用方取消。
- 包含 made no progress：超过 `batch_idle_timeout` 没有进度。
- 包含 maximum duration：超过 `batch_max_duration`。
- 检查数据库慢查询、磁盘 I/O、网络数据源和生成器是否持续上报进度。

### 生成成功但线上没有变化

依次确认：

1. job `result.output` 是否为预期目录；
2. Web 服务器 root/alias 是否指向同一目录；
3. 文件修改时间和内容是否已更新；
4. 是否还需要对象存储同步；
5. CDN、浏览器或反向代理缓存是否未刷新；
6. 访问 URL 是否命中旧发布版本。

### 首页或栏目没有新文章

- 文章详情自动生成不代表聚合页自动刷新。
- 检查文章状态、审核状态和正式发布关系。
- 检查栏目名称是否匹配适配器配置。
- 重新生成所属栏目；首页引用该栏目时再生成首页。

### 下线文章仍能访问

- 确认下线操作已经清理发布关系。
- 查看后台详情删除静态化日志是否成功。
- 手工执行详情删除；然后刷新原栏目和首页。
- 若文件已删除但公网仍可访问，检查 CDN/缓存和备用源站。

### 输出路径被拒绝

请求 path 必须是绝对非根目录，且不能与模板源目录重叠。生产环境应固定输出根，不接受来自普通用户的任意路径。

### 数据库连接失败

- 验证 DSN 环境变量名和值；
- 检查数据库名与 `database.schema`；
- 检查账号来源 IP、TLS、字符集和时区；
- 使用只读查询验证连接，不要在排障时运行迁移或修改生产数据。

## 4. 备份

上线或大版本升级前至少备份：

- 当前二进制和配置；
- 环境变量来源或密钥管理版本号；
- 当前完整静态产物目录；
- Portal CMS 数据库（由数据库备份策略负责）；
- 外部上传文件或对象存储资源。

不要把生产 `.env`、SQL dump 或用户上传内容提交到本仓库。

## 5. 升级和回滚检查表

升级前：

- [ ] `go test ./...`、Race、Vet 通过。
- [ ] 新版本在隔离目录完成真实数据生成。
- [ ] 文件集合、关键 HTML 和媒体地址扫描通过。
- [ ] 原门户源工程 Git tracked diff 为空。
- [ ] 已备份当前二进制、配置和静态产物。
- [ ] 已准备上一版本快速回滚路径。

升级后：

- [ ] `/healthz` 正常。
- [ ] 后台显示在线，Token 调用正常。
- [ ] 单页面或单文章生成成功。
- [ ] 全站任务成功且生成数量合理。
- [ ] 首页、栏目、详情、统计图表和媒体抽查正常。
- [ ] 日志没有旧域名、内网地址、密码或 Token 泄漏。

## 6. 安全基线

- 静态化 HTTP 服务不直接暴露公网。
- 每个站点使用独立随机 Token，定期轮换。
- 数据库账号使用最小只读权限。
- 模板源目录只读，输出目录单独授权。
- systemd 使用专用非 root 用户和 `NoNewPrivileges`。
- 不在命令行、Git、日志或工单中粘贴生产密码和 Token。
- 管理后台负责用户权限、防重放、签名和审计；浏览器不直接访问静态化服务。
- 输出目录由 Web 服务器只读提供，不允许执行脚本或目录上传。

## 7. 产物扫描

根据环境维护禁止模式列表，例如：

```bash
rg -n -i \
  'demo\.miic\.com\.cn|caamm/uploads|10\.[0-9]+\.[0-9]+\.[0-9]+|[A-Z]:\\' \
  /srv/portal-static/caam/site -g '*.html'
```

扫描规则应覆盖实际旧域名、内部网段、历史上传目录和 Windows 路径。命中结果必须人工判断，不能简单批量替换正文。

## 8. 灾难恢复

当新生成结果错误但进程仍正常时：

1. 暂停管理后台继续提交静态化任务。
2. 保存失败 job、日志和错误产物用于分析。
3. 恢复上一份完整静态目录备份或切回上一发布版本。
4. 清理 CDN/代理缓存并验证关键 URL。
5. 在隔离输出目录复现并修复问题。
6. 通过完整验收后再恢复正式生成。

不要直接修改生成后的 HTML 作为长期修复；下一次生成会覆盖手工改动。正确修复位置应是数据、模板、适配器配置或生成器代码。
