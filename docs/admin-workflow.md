# 管理后台使用指南

本文说明内容人员如何通过 `dia-platform/business/portal` 管理内容并配合 `portal-static` 发布页面。后台工程和静态化平台是两个独立进程：后台维护数据库、审核和权限，静态化平台读取已发布数据并生成文件。

## 1. 首次使用前检查

由管理员在“基础配置 → 静态化设置”完成：

| 字段 | 填写内容 |
| --- | --- |
| 静态化输出路径 | 静态化服务所在主机上的绝对目录，例如 `/srv/portal-static/caam/site` |
| 静态化程序访问地址 | 后台服务能够访问的地址，例如 `http://127.0.0.1:9142` |
| 静态化程序访问令牌名 | 令牌所在环境变量名称，例如 `CAAM_STATIC_TOKEN` |
| 首页整体变灰 | 按当前业务要求开启或关闭 |

注意：令牌名不是令牌值。后台和静态化服务两个进程都必须配置该环境变量，并使用相同值。

保存设置后进入“基础配置 → 静态化管理”，确认服务状态在线。若离线，先联系运维，不要通过重复点击生成按钮解决。

## 2. 内容发布流程

```text
新建草稿
  ↓
选择页面/栏目并完善标题、正文、封面、发布时间
  ↓
提交栏目审核
  ↓
所有栏目审核通过
  ↓
后台写入正式发布关系并将文章设为已发布
  ↓
后台尽力生成文章详情页
  ↓
按影响范围刷新栏目、首页或全站
  ↓
检查静态化任务与线上页面
```

只有完成审核并建立正式发布关系的内容才应进入静态产物。草稿、审核中、审核失败、已下线或没有发布关系的文章不会因“生成全站”而变成已发布内容。

## 3. 发布后应该刷新什么

| 内容变化 | 推荐操作 | 原因 |
| --- | --- | --- |
| 新文章审核通过 | 详情会自动尽力生成；随后刷新所属栏目 | 栏目列表需要出现新文章 |
| 文章标题、封面、摘要、排序变化 | 重新生成文章，并刷新所属栏目；若首页引用则刷新首页 | 聚合页保存了文章摘要信息 |
| 首页头条、轮播、统计等栏目变化 | 生成首页 | 只刷新文章详情不会更新首页聚合内容 |
| 栏目下多篇文章或分页发生变化 | 生成对应栏目；范围不清楚时生成全部栏目页 | 分页数量和前后页可能变化 |
| 页面模板或公共资源变化 | 生成全站 | 需要保证所有页面使用同一版本 |
| 大批量导入、迁移或配置变更 | 生成全站 | 一次建立完整一致的基线 |
| 文章下线或删除 | 后台会尽力删除详情；随后刷新原所属栏目和首页 | 聚合页仍可能保留旧链接 |
| 首页整体变灰切换 | 生成首页；需要全站一致时生成全站 | 灰度参数只在支持的页面生成时生效 |

“尽力生成/删除”意味着静态化服务暂时不可用时，后台发布或下线业务仍可完成，但静态文件可能未同步。内容人员必须查看静态化日志；失败时服务恢复后手工补做。

## 4. 静态化管理的四种批处理

### 4.1 生成全站

生成主页面、全部栏目列表、全部已发布文章详情和所需资源。适合首次上线、大批量变更、模板升级和一致性修复。

全站生成在临时目录完成并校验，通过后才替换目标目录。运行时间通常最长，同一站点同时只能有一个批任务。

### 4.2 生成首页

生成适配器定义的全部主页面。CAAM 包括首页及协会概况、协会工作、统计数据、会员专区和党建专区；其他门户由各自适配器定义，但操作入口相同。

### 4.3 生成栏目页

生成全部栏目列表和分页。文章数量、排序、置顶或栏目归属变化后使用。

### 4.4 生成详情页

重新生成全部已发布文章详情。适合详情模板更新或批量正文/媒体修正。

## 5. 单项操作

静态化管理页面支持按范围重新生成：

- 主页面：按页面名重新生成；
- 栏目：按栏目名称重新生成列表和分页；
- 详情：按文章 ID 重新生成；
- 详情删除：删除指定文章的静态文件。

单项操作是同步请求，成功后立即返回结果。批任务运行期间单项操作会被拒绝，等待批任务结束后再执行。

删除详情文件前应先在后台完成文章下线。静态化服务会拒绝删除仍处于可发布状态的文章，避免数据库与文件状态冲突。

## 6. 任务状态

批任务提交成功后，后台每 3 秒轮询一次：

| 状态 | 含义 | 操作建议 |
| --- | --- | --- |
| `queued` | 已接收，等待执行 | 正常等待 |
| `running` | 正在读取和生成 | 查看阶段与进度，不要重复提交 |
| `succeeded` | 已成功发布 | 检查生成数量和关键页面 |
| `failed` | 生成失败 | 查看错误与日志，修复后重新执行 |
| `interrupted` | 被取消、无进度超时或超过最长时间 | 确认原因后重新执行 |

任务完成不等于业务内容一定正确。正式发布仍需要抽查首页、目标栏目、目标文章和媒体链接。

## 7. 推荐日常操作

### 发布单篇文章

1. 编辑文章并选择正确栏目。
2. 完成审核，确认状态为“已发布”。
3. 在静态化日志确认详情生成成功。
4. 重新生成所属栏目。
5. 如果文章进入首页模块，再生成首页。
6. 打开线上页面抽查标题、时间、正文、封面和链接。

### 下线或删除文章

1. 在后台执行下线或删除，不要先手工删除数据库记录。
2. 确认详情静态文件删除日志成功。
3. 刷新原所属栏目和可能引用它的首页。
4. 确认旧详情 URL 已不可访问，列表和首页也不再显示。

### 大批量内容调整

1. 先在非生产输出目录生成全站并抽查。
2. 确认草稿和未审核内容未进入产物。
3. 在业务低峰执行正式全站生成。
4. 等待状态为 `succeeded`，记录任务 ID 和文件数量。
5. 检查线上入口、栏目分页、文章详情和媒体资源。

## 8. 常见提示

- “静态化服务已停止”：检查服务进程、访问地址和网络。
- `unauthorized`：后台进程与静态化进程的 Token 不一致，或令牌名填写错误。
- “已有任务正在执行”：等待当前批任务完成；不要并发生成同一站点。
- “文章未发布”：先完成审核和发布关系，不要靠静态化接口绕过业务流程。
- “栏目不存在/不唯一”：检查后台栏目名称和站点配置，栏目名称必须与适配器配置匹配。
- 输出路径错误：必须使用静态化服务主机上的绝对非根目录，且不能指向模板源工程。
- 页面生成成功但线上未变化：检查 Web 服务器根目录、CDN/对象存储同步和缓存，不要只检查生成任务。

更多故障处理见[运维与排障手册](operations.md)。
